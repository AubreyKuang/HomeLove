# 像素小屋 · HomeLove的玩法探索

沿用游戏内时间、来访时段和居民偏好。用现有约会地点验证玩家会不会根据当天安排改变选择。

## 第二轮　委托的交付方式

| ID | 玩家读取什么，再做什么 | 进展、代价与熟练策略 | 初筛 |
| --- | --- | --- | --- |
| HL-02b | 手里的食材、交付地点与接下来的安排 → 直接交付，或留下来和居民一起做 | 两种交法都完成委托。一起做留下可回看的相处片段，但占用当天的时间。 | 已有可玩版本。[规则](features/shared-outings/design.md#委托交付与窗边点心) |
| HL-03a | 明天的居民来访和自己的安排 → 约一个具体时段 | 预留一次相处机会。玩家会避开撞班，但仍可能改变主意。 | 待测。需要观察预约是否给日程增加负担。 |
| HL-05 | 两件委托品的库存和做饭需求 → 交一种，留一种自用 | 用不同库存完成同一委托。 | 与现有的两种备选物品重复。 |
| HL-06 | 村镇下雨与居民去处 → 顺路当面交，或托邻居转交 | 减少走路，但失去当面交谈。熟练玩家会按日程和见面需求选择。 | 待测。委托人离场时也要能知道转交结果。 |
| HL-07 | 菜地成熟日和来信期限 → 选更早能交的委托，或等一个更合适的委托 | 把种植规划变成接单前的选择。 | 待测。当前只有一封进行中的委托，需要先验证玩家是否想在多封来信中挑选。 |

**HL-02b 的试玩范围。** 首版只用顾言的草莓／饼干委托。已验证关门前来不及时仍可直接交付，以及共同制作、报酬和画册记录随同一次结算保存。时长和营业条件见上方规则。

**两种局面。** 在来访结束前只剩 15 分钟可以办另一件事时，直接交付还能赶上。下午有空、玩家想和顾言相处时，留下做点心能得到一段不同的经历。现有委托已经有交付期限、两项备选物品与首次纪念卡，顾言也有咖啡店时段。原型可以复用这些入口。[委托定义与结算](../cottage-activities.js) · [交付入口](../js/daily-life.js) · [居民日程](../js/residents.js)

**最小试玩。** 用相同的委托和背包，给玩家两份日程，一份还有 15 分钟要赴约，一份接下来有 60 分钟空档。记录选法，以及玩家能否在确认前说清共同制作消耗的时间。如果连空档充裕时也没有人愿意留下，先验证共同制作本身是否有吸引力。人工试玩待进行。

### 出门前的安排

首版只有当面打开交付菜单才说明可以一起做。现已把所需材料和可开始的时段写入来信及日记，日记可直接安排步行路线。接单后，顾言营业时会去咖啡店，即使已同居也可以在那里碰面。

Chrome 手机尺寸下，以已认识顾言、背包有草莓的存档为起点。通过信箱接单，打开日记，实际沿路线走到咖啡店，通过顾言的对话完成点心并检查画册记录。顾言由居民日程到店，检查没有直接移动他。下一次真人对照仍要看玩家读完信后会不会主动留出下午的时间。

## 第三轮　错过当面交付

| ID | 玩家读取什么，再做什么 | 进展、代价与熟练策略 | 依据与最小试玩 |
| --- | --- | --- | --- |
| HL-06a | 委托截止日、库存、居民日程 → 当面交付或把物品留在自家信箱 | 留物当日即完成交付要求，次日起可领物资。当面交付立即拿报酬和好感，能留下相处记录。 | 从 HL-06 的「找邻居转交」改用已有信箱。给玩家同一个已接委托，一次是最后一晚且居民已离开，一次仍能在路上遇到居民。记录两次选法及对代交报酬的预期。已有可玩版本。[规则](features/shared-outings/design.md#信箱代交) |
| HL-03b | 两人的下一次空档 → 约一个可取消的见面时段 | 保留会面机会，但占用明天的时间。计划有变时可取消。 | 纸面先给一份会撞班的预约和一份顺路的预约，观察重排日程是否比直接代交更符合玩家目标。待测。 |
| HL-08 | 田里成熟日和两种备选物品 → 提前留下一种库存或等收成 | 把库存从做饭或送礼挪到委托。熟练玩家看成熟日和截止日。 | 与既有备选交付重叠。用一份两天后收成和一份当天到期的委托推演，只有提前预留会改变后续可用库存时才值得实测。 |
| HL-09 | 村镇营业时间与顺路地点 → 选择一个中转点 | 降低绕路代价，但需要比较营业窗，也可能错过当面交付。 | 先用同一个背包、两个营业窗口和一条固定路线做纸面检查。待测，信箱原型足够先观察玩家是否需要代交。 |
| HL-10 | 手中物品 → 在家立即代交并立刻获得同样的好感和回忆 | 在需要专程去找人时，代交以更少时间获得相同结果。 | 淘汰。居民已经在身边时结果仍相同，选择只取决于谁更近。 |

代交已用回归验证截止日投递、隔天领取、读档和重复领取。真人试玩待观察玩家是只在赶不上时用信箱，还是愿意拿即时好感换一段空闲时间。

## 第四轮　把见面排进明天

| ID | 玩家读取什么，再做什么 | 进展、代价与熟练策略 | 依据与最小试玩 |
| --- | --- | --- | --- |
| HL-03c | 明天的空档、地点和时长 → 约上午花园、下午池塘或今天就去 | 换来一个确定的见面时段，需要预留出行和约会时间。玩家可因第二天已有安排改变地点。 | 将 HL-03b 改为两个地点和固定时段，并允许取消。用已有约会结算。给同一位玩家两份行程，其中一份下午要交委托，看是否改选。已有可玩版本。[规则](features/shared-outings/design.md#约明天见) |

| HL-13 | 当前好感 → 预订立即获得完整约会收益 | 不需要出门、等候或履约。 | 淘汰。立即预订能重复替代完整约会。 |

浏览器对照覆盖预订、读档、取消以及次日走到现场开始约会。是否会因地点偏好和时间冲突主动重排一天，仍待真人试玩。

## 第七轮　把饭带进当天的行程

| ID | 玩家读取什么，再做什么 | 进展、代价与最小试玩 |
| --- | --- | --- |
| HL-15a | 当前饱腹、目的地、两个截止时间 → 在家热着吃或留到市集 | 用同一份便当。家中恢复更多，市集能晚吃并省去折返。已有可玩版本；给玩家两条早晨路线，观察是否因去向而换吃饭地点。 |
| HL-19 | 居民空档和两人的需要 → 一人吃饱或分给居民 | 用自身饱腹换相处，时间和地点取决于谁到场。先纸面比较一位顺路居民和一位需要等候的居民。未知：玩家会不会只看好感收益。 |
| HL-20 | 明日预报和预计采买路线 → 提前准备便当或等市集供餐 | 提前占用库存可以锁定一顿饭，等到店则要承担营业和货源风险。先用两份可见预报和同一营业窗检验是否真有改选理由。 |
| HL-21 | 背包里的食材和路上可采集的配料 → 先吃原份或凑齐配料再吃 | 等待时饱腹继续下降，成品恢复更多。先比较一次顺路补料和一次绕行。未知：奖励是否值得增加采集步骤。 |

最小试玩一局让玩家早上留在小屋照料菜地，另一局让玩家午前出门、午后要在村镇赴约。观察他们会不会先读日记、能否自行找到长椅、以及少恢复的饱腹是否足以改变选择。真人试玩待进行。[规则](features/shared-outings/design.md#早餐便当)

## 第八轮　便当要不要分一半

## 第十二轮　约好了却下雨

| ID | 玩家读取什么，再做什么 | 进展、代价与最小试玩 |

| HL-30a | 降雨、当前位置和下一件事 → 保留户外约会，或在同一时段改到小屋喝茶 | 地点改变步行距离，喝茶时长与收益介于散步和完整约会之间。已有可玩版本。分别从小屋和池塘附近出发，给相同的下午约会，观察选择是否随路程改变。 |

| HL-32 | 雨天限定的村中景象和时间 → 准时赴约后沿途找一种雨天景物 | 见面后增加一个探索目标，消耗当天空档。先试一条能顺路经过景物的路线和一条需要折返的路线，观察是否值得绕路。 |

真人试玩待观察玩家会不会为路程和后续行程改地点，以及室内喝茶是否经常挤掉户外选择。[规则](features/shared-outings/design.md#雨天改到小屋喝茶)
